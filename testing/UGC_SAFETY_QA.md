# UGC安全機能 2アカウントQA手順（通報・ブロック）

最終更新: 2026-10-02

`feat/ugc-safety`ブランチで実装した「通報」「ブロック」は、自分自身のコンテンツには
メニュー自体が表示されない設計のため、**実アカウント2つを使わないと動作確認できない**。
このドキュメントは、ユーザー本人が既存の別Google/Appleアカウントを使って手動で行うQA手順。

**前提**:
- 新しいアカウントは作成しない。既存の別アカウント（サブのGoogleアカウント等）を使う
- 本番環境ではなく、まずは`npm run dev`のローカル環境（`http://localhost:3000/trade`）で実施すること
- **Firestore Rulesが未デプロイの状態では、通報・ブロックの書き込みが`permission-denied`で失敗する**
  （詳細は本レポートの「PERMISSION DENIED ROOT CAUSE」参照）。Rulesデプロイ後に実施すること

---

## STEP 0: 準備

1. 2つのブラウザ（またはシークレットウィンドウ/別ブラウザプロファイル）を用意する
   - ブラウザA: Account Aでログイン
   - ブラウザB: Account Bでログイン
2. どちらも `http://localhost:3000/trade` を開く

---

## STEP 1: Account Aで投稿・コメントを作成

**ブラウザA（Account A）で操作**

1. 画面上部の投稿フォームでカードは選ばず、フレンドID（適当な16桁の数字、例: `1111222233334444`）だけ入力して「トレード募集を投稿」を押す
2. 投稿一覧に自分の投稿が表示されることを確認
3. その投稿の「コメントする」ボタンを押し、コメント欄に適当な文章（例:「よろしくお願いします」）を入力して送信する
4. コメントが表示されることを確認

ここまでで、ブラウザBから通報・ブロックする対象（Aの投稿・Aのコメント）ができた状態。

---

## STEP 2: Account Bから通報する

**ブラウザB（Account B）で操作**

### 2-1. Aの投稿を通報
1. トレード一覧でAの投稿を見つける（ニックネーム横に「…」メニューが表示されているはず）
2. 「…」→「通報する」を押す
3. 通報理由を1つ選ぶ（例:「その他」）、詳細欄は任意で入力
4. 「通報する」ボタンで送信 → 「通報を受け付けました」と表示されることを確認
5. モーダルを閉じ、もう一度「…」メニューを開く → ボタンが「通報済み」になっていて押せないことを確認（**二重通報防止の確認**）

### 2-2. Aのコメントを通報
1. Aの投稿の「コメントする」を押してコメント欄を開く
2. Aのコメント横の「…」メニュー→「通報する」
3. 2-1と同様に理由を選んで送信し、「通報を受け付けました」を確認

---

## STEP 3: Account Bからブロックする

**ブラウザB（Account B）で操作**

1. Aの投稿の「…」メニュー→「ユーザーをブロック」を押す
2. **確認: トレード一覧からAの投稿が即座に消える**（ページ再読み込み不要）
3. 画面を更新（リロード）しても、Aの投稿が表示されないままであることを確認
4. 別のAの投稿があれば、そのコメント欄を開き、**Aのコメントもコメント一覧から消えている**ことを確認

---

## STEP 4: ブロック解除

**ブラウザB（Account B）で操作**

1. 右上のアカウントメニュー→「トレード投稿」（`/mypage/trades`）を開く
2. 「ブロックしたユーザー」セクションにAが表示されていることを確認
3. 「ブロック解除」ボタンを押す
4. トレード掲示板（`/trade`）に戻り、**Aの投稿・コメントが再表示される**ことを確認

---

## STEP 5: 追加確認

### 5-1. Aは自分宛てのBの通報データを読めない
**ブラウザA（Account A）で操作**
1. ブラウザの開発者ツール（コンソール）を開く
2. 以下を実行し、エラー（`permission-denied`）になることを確認:
   ```js
   // Account Aのコンソールで実行。Bが通報したreportsドキュメントを覗き見しようとする想定
   // (実際のreportIdはBが通報した時にFirestore Consoleで確認できる)
   import("firebase/firestore").then(async ({ getFirestore, doc, getDoc }) => {
     const db = getFirestore();
     try {
       const snap = await getDoc(doc(db, "reports", "<Bが通報したreportId>"));
       console.log("読めてしまった(NG):", snap.data());
     } catch (e) {
       console.log("読めなかった(OK, 期待通り):", e.code);
     }
   });
   ```
   `permission-denied`であればOK（Firestoreルールの`reports`読み取り制限が効いている）

### 5-2. Bは自分自身の投稿に「通報」が出ない
**ブラウザB（Account B）で操作**
1. Bが投稿したトレード投稿を自分のブラウザで見る
2. ニックネーム横に「…」メニュー自体が表示されないことを確認（自己通報の誤操作防止）

### 5-3. 自分自身をブロックできない
- 上記5-2と同じ理由で、自分の投稿には「…」メニュー自体が出ないため、UI上はそもそもブロックボタンにたどり着けない
- 念のため開発者ツールのコンソールで直接書き込みを試す場合:
  ```js
  import("firebase/firestore").then(async ({ getFirestore, doc, setDoc, serverTimestamp }) => {
    const db = getFirestore();
    const myUid = "<自分のUID>"; // Firebase Consoleの Authentication タブで確認
    try {
      await setDoc(doc(db, "users", myUid, "blockedUsers", myUid), {
        blockedUid: myUid, blockedNickname: null, createdAt: serverTimestamp(),
      });
      console.log("書き込めてしまった(NG)");
    } catch (e) {
      console.log("書き込めなかった(OK, 期待通り):", e.code);
    }
  });
  ```
  `permission-denied`であればOK（ルールの`blockedUid != userId`チェックが効いている）
